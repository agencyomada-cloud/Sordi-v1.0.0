# Hooks Reference

Every file in `apps/desktop/src/hooks/` (36 files), one entry per hook module, describing what entity/concern it manages and which TanStack Query hooks it exposes. All hooks that touch business data call through the `db` object in `apps/desktop/src/lib/database.ts` (see [`frontend.md`](./frontend.md)).

| Hook file | Description |
|---|---|
| `useActiveCompany.ts` | Reads the active `companies` row (company profile: name/logo/fiscal identity) from `useWorkspace`: `useActiveCompany()` (read), `useUpdateActiveCompany()` (mutation, invalidates `["companies"]`); also exports plain helpers `getCompanyPhoneList()`/`getCompanyExtraInfoList()` for parsing the JSON-encoded `phones`/`extra_info` columns. |
| `useAppDataDir.ts` | `useAppDataDir()` — caches Tauri's `appDataDir()` forever (`staleTime`/`gcTime: Infinity`); plus plain async helpers `resolveAppDataFileUrl()` and `resolveAppDataAbsolutePath()` for turning a DB-relative path (employee photos/documents) into a webview `asset://` URL or an absolute FS path. |
| `useAuth.ts` | Non-TanStack-Query hook managing the local password/session gate: exposes `user`, `loading`, `needsSetup`, `isTauri`, `signIn(password, login?, rememberMe?)`, `signOut()`. Desktop mode calls Tauri commands `has_password_set`/`set_password`/`check_password`; web-preview mode falls back to a hardcoded `admin`/`admin` demo login. Session flag stored in `sessionStorage` (always) and `localStorage` (only if "remember me"). |
| `useClientAdvances.ts` | Client prepayments/advances: `useClientAdvances(clientId)`, `useAddClientAdvance()`, `useUpdateClientAdvance()`, `useDeleteClientAdvance()` — invalidate `["client-advances", clientId]` and `["clients"]` on success, with French success/error toasts. |
| `useClientDraftProducts.ts` | A client's "draft" product queue (products staged before invoicing): `useClientDraftProducts(clientId)`, `useAddClientDraftProduct()`, `useUpdateClientDraftProductQuantity()`, `useDeleteClientDraftProduct()`, `useClearClientDraftProducts()`. |
| `useClientProducts.ts` | `useClientProducts(clientId, filters?)` — read-only query summarizing a client's purchased products (quantity/amount per product, optionally filtered by product/month/year), 30s `staleTime`. |
| `useClients.ts` | Core client CRUD scoped to `activeCompanyId`: `useClients()`, `useClient(id)`, `useClientOverviewStats(id?)` / `useClientOverviewStatsMap()` (status-badge stats), `useCreateClient()`, `useUpdateClient()`, `useDeleteClient()` — all validate via `clientSchema` (Zod), log to `db.history`, and toast in French. |
| `useContracts.ts` | Service contracts: `useContracts()` (company-scoped), `useProjectContracts(project_id)`, `useCreateContract()`, `useDeleteContract()` — invalidates `["contracts"]`. |
| `useCountUp.ts` | Pure animation hook, no query — `useCountUp(target, duration=900)` eases a number from 0 to `target` via `requestAnimationFrame`, used for dashboard KPI numbers. |
| `useDashboardStats.ts` | `useDashboardStats(year?, months?)` — single aggregated Rust-backend call (`db.dashboard.getStats`) mapped from snake_case to camelCase, covering revenue/expenses/payments/growth/margins; uses `keepPreviousData` for smooth period switching. |
| `useDebouncedValue.ts` | Pure utility, no query — `useDebouncedValue(value, delayMs=150)` debounces any value (used for search inputs). |
| `useDeliveryNotes.ts` | Delivery notes (bons de livraison): `useDeliveryNotes(clientId?, isInvoiced?)`, `useDeliveryNote(id)` (both enrich with client + items), `useCreateDeliveryNote()`, `useUpdateDeliveryNote()`, `useSetDeliveryStatus()`, `useDeleteDeliveryNote()`, `useGenerateInvoiceFromDeliveries()` (invokes `generate_invoice_from_delivery_notes`). Also exports the `DeliveryNote`/`DeliveryNoteItem`/`CreateDeliveryNoteData` TypeScript types reused elsewhere. |
| `useEmployeeDocuments.ts` | Per-employee document attachments: `useEmployeeDocuments(employeeId)`, `useAddEmployeeDocument()`, `useDeleteEmployeeDocument()`. |
| `useEmployees.ts` | `useEmployees()` (returns query + bundled `createEmployee`/`updateEmployee`/`deleteEmployee` mutations), plus `useEmployeeTaskWorkload()`, `useSetEmployeePhoto()`, `useRemoveEmployeePhoto()`. |
| `useExpenses.ts` | Company expenses: exports `EXPENSE_CATEGORIES` constant; `useExpenses(monthPeriod?, projectId?)`, `useCreateExpense()` (Zod-validated, invalidates dashboard-stats and project profitability too), `useDeleteExpense()`, `useExpenseStats(monthPeriod?)` (client-computed totals by category). |
| `useGlobalSearch.ts` | `useGlobalSearch(rawQuery)` — debounces (150ms) and queries `db.search.global`, company-scoped, min 2 chars (`isBelowMinLength` flag distinguishes "too short" from "no results"). Powers the sidebar's `⌘K` command palette. |
| `useIntegrations.ts` | Not a TanStack Query hook — derives an `Integrations` status object from `useSettings()`: Gmail is "connected" if `smtp_email`+`smtp_app_password` are set; Sheets/Calendar are hardcoded `comingSoon: true` placeholders (no real OAuth backend yet). |
| `useInvoices.ts` | Core invoicing (invoices/proformas/avoirs): `useInvoices(status?, invoiceType?)`, `useInvoice(id)` (enriches with client + items), `useCreateInvoice()`, `useUpdateInvoice()`, `useUpdateInvoiceStatus()`, `useDeleteInvoice()`, `useConvertProforma()`, `useInvoiceStats()` (currently a TODO stub returning zeros). All mutations validate via `createInvoiceSchema`, log to `db.history`, invalidate `dashboard-stats`/`client-products`. |
| `useLanguage.ts` | App-wide i18n: `useLanguage()` reconciles i18next's in-memory language, `localStorage` cache, and the durable `settings.current_language` value; exposes `language`, `meta`, `setLanguage()`, `isRtl`. |
| `useLicense.ts` | Licensing status: `useLicenseStatus()`, `useActivateLicense()`, `useLicenseBackgroundVerify()` (silent once-per-session re-verify). Includes an **omada-agency-branch-only `LICENSE_BYPASS`** short-circuit (`VITE_LICENSE_BYPASS=true` env flag) that always reports `state: "active"` without touching the real Rust licensing code — the frontend counterpart to the Rust `omada_bypass` Cargo feature. |
| `useOrders.ts` | Purchase/sales orders (bons de commande): `useOrders()`, `useOrder(id)`, `useOrderItems(orderId)`, `useCreateOrder()`, `useUpdateOrder()`, `useUpdateOrderStatus()`, `useDeleteOrder()`, `useNextOrderNumber()`. |
| `usePageHeader.tsx` | React Context (not a query hook) powering the top `Header.tsx` breadcrumb/title: `PageHeaderProvider`, `usePageHeaderState()` (read, falls back to a static path→title map), `useSetPageHeader(title, breadcrumb?)` (called by detail pages to override it). |
| `usePartners.ts` | Equity partners/associates: `usePartners(year?, months?)`, `usePartnerWithdrawals(partner_id)`, `useCreatePartner()` (surfaces the Rust "equity total exceeds 100%" validation error verbatim), `useUpdatePartner()`, `useDeletePartner()`, `useRecordPartnerWithdrawal()`, `useDeletePartnerWithdrawal()`. |
| `usePayments.ts` | Invoice payments: `usePayments(invoiceId?)`, `useCreatePayment()`, `useUpdatePayment()`, `useDeletePayment()`, `useRestorePayment()` (re-creates a deleted payment for a 5s "Annuler" undo toast — a new id, not a true undo), `usePaymentAttachments(paymentId)`, `useAddPaymentAttachment()`, `useDeletePaymentAttachment()`. |
| `usePayroll.ts` | Payroll module: attendance import `useImportPunchRecords()`; absence stats `useEmployeeAbsenceStats()`; advances `useEmployeeAdvances()`/`useEmployeeAdvanceTotals()`/`useCreateEmployeeAdvance()`/`useSetEmployeeAdvanceDeducted()`; payroll runs `usePayrollRuns()`/`useRunPayroll()`/`useUpdatePayrollPaid()`/`useUpdatePayrollRun()`/`useDeletePayrollRun()`; manager dashboard `usePayrollDashboardStats(month)`, `useUnmappedDeviceCodes(month?)` (device codes from imported punches with no matching employee). |
| `useProducts.ts` | Product/service catalog: `useProducts()`, `useCreateProduct()`, `useUpdateProductPrice()` (Zod-validated), `useUpdateProduct()`, `useDeleteProduct()`. |
| `useProjectDeliverables.ts` | Per-project deliverables: `useProjectDeliverables(projectId)`, `useCreateProjectDeliverable()`, `useUpdateProjectDeliverable()`, `useDeleteProjectDeliverable()`. |
| `useProjectTasks.ts` | Per-project tasks (kanban-style statuses): `useProjectTasks(projectId)`, `useCreateProjectTask()`, `useUpdateProjectTask()`, `useUpdateProjectTaskStatus()`, `useDeleteProjectTask()` — all invalidate both the task list and project-stats caches. |
| `useProjects.ts` | Core projects module: `useProjects()`, `useProject(id)`, `useProjectStats(project_id?)`/`useProjectStatsMap()` (planned-budget vs. TTC consumption), `useProjectProfitability(project_id)` (real HT revenue minus direct costs), `useCreateProject()`, `useUpdateProject()`, `useDeleteProject()`, `useAssignInvoiceToProject()`, `useSetFreelancerPaymentStatus()`, `useAssignFreelancePayment()`, `useFreelancePayments()`. |
| `useSettings.ts` | Flat key/value app settings store (`Settings` interface covers PDF theme/font, logo, **stamp_data/signature_data** (Cachet/Signature), SMTP credentials, language, etc.): `useSettings()` (merges the KV store with `company_*` fields projected from the active Company row), `useUpdateSetting()`, `useUpdateSettings()`. |
| `useSidebarCounts.ts` | Derives sidebar badge counts (not separate endpoints) from existing invoices/orders/deliveries/activity-log queries: unpaid invoices, pending orders, un-invoiced deliveries, unread history entries (tracked via a `localStorage` "last seen" timestamp). |
| `useSuppliers.ts` | Suppliers: `useSuppliers()`, `useSupplier(id)`, `useSupplierPurchaseTotalsMap()` (sum of expenses per supplier), `useCreateSupplier()`, `useUpdateSupplier()`, `useDeleteSupplier()`, `useRestoreSupplier()` (undo-toast re-create, same pattern as `useRestorePayment`). |
| `useSystemReset.ts` | `useResetToFactoryState()` — the single destructive mutation behind Settings' factory-reset flow, wiping all transactional data (clients, suppliers, invoices, payments, expenses, contracts, projects, deliveries, orders, activity logs) for the active company; never touches company profile, employees, partners, products, or settings; invalidates the entire query cache on success. |
| `useWorkspace.tsx` | **Multi-company context** — the architectural backbone every company-scoped hook reads from. `WorkspaceProvider` loads `db.companies.getAll()` once (5-min `staleTime`), persists the selected `activeCompanyId` to `localStorage` (`sordi.workspace.activeCompanyId`), and auto-falls-back to the first company if the stored id no longer exists. Exposes `useWorkspace()`: `{ activeCompanyId, companies, isReady, switchCompany(id), createCompany(data), isCreatingCompany }`. `switchCompany` calls a blanket `queryClient.invalidateQueries()` (no args) so no cross-company data can linger on screen; throws if used outside the provider. See [`frontend.md`](./frontend.md) for the full walkthrough. |

**Total: 36 hook files**, covering every business domain in the app plus cross-cutting concerns (auth, i18n, workspace, pure UI utilities).
